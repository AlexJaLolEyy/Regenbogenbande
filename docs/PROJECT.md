# Regenbogenbande - Private Clip Platform

A private platform for the Discord friend group "Die Regenbogenbande" to archive and share **videos**, **pictures** and **quotes** from gaming moments.

## Tech stack

| Layer      | Technology                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| Frontend   | Next.js 16 (App Router), React 19, Tailwind CSS 4, HeroUI, Framer Motion   |
| Backend    | Server Actions + API routes                                                |
| Database   | PostgreSQL on Supabase, Prisma 7 (`@prisma/adapter-pg`)                    |
| Auth       | better-auth (Discord login + anonymous guests)                             |
| Storage    | Cloudflare R2                                                              |
| Processing | FFmpeg (compression, thumbnails) in `/api/compress`                        |
| Charts     | chart.js (analytics page)                                                  |
| Icons      | lucide-react (Discord logo is a local SVG)                                 |
| Hosting    | Vercel                                                                     |

Package manager: **bun** (`bun.lock`). Do not use `npm install`.

## Roles and access

`guest` (anonymous or no session) < `member` < `admin` < `owner`. Roles live in the DB; `getEffectiveRole` in `src/lib/auth-utils-shared.ts` resolves them. Guests only see public content. Uploading needs `member` or higher, publishing is owner-only, deleting is allowed for the uploader and admins. Disabled users have no session (`getSession` returns null).

## Directory layout

```
src/
  app/
    (content)/{videos,pictures,quotes}/   routes, upload/edit server actions
    admin/                                users, content, categories
    analytics/                            /analytics (personal + group stats)
    api/                                  compress, upload-picture, upload-from-url, categories/upload
  lib/
    actions/                              server actions (comments, ratings, views, ...)
    analytics/                            SQL queries for the analytics page
    components/                           all UI (videos/, pictures/, quotes/, ui/, shared/, ...)
    db/{selects,mutations,shared.ts}      Prisma queries, list-query builder
    queries/                              TanStack Query hooks and keys
    api-auth.ts, safe-fetch.ts            API guard, SSRF-safe fetch
    env.ts                                required env var validation (runs at startup)
prisma/                                   schema + migrations
docs/                                     this folder
```

`src/components` only contains components generated by tools (shadcn etc.); app UI lives in `src/lib/components`.

## Conventions

- All server actions and API routes check the session first (`requireAuth`, `guardApi`, `requireUploadPermission`, ...).
- Storage URLs from clients are validated with `assertOwnStorageUrl` before they are saved.
- Ratings are denormalised (`ratingAvg`, `ratingCount`) and updated in the same transaction as the rating.
- Views are logged in `ContentView` with a 30 minute dedupe; analytics read from there.
- Mutations that change public content call `revalidateTag('analytics', 'max')`.

## Environment

Copy `.env.example`. Prisma CLI uses `.env.development` by default and `.env.production` when `PRISMA_ENV=production` (see `prisma.config.ts`); migrations use `DIRECT_URL`, the app uses the pooled `DATABASE_URL`.
